# Диаграммы UML — Tsunami

Данный каталог содержит набор UML-диаграмм, раскрывающих статическую и динамическую архитектуру инструмента нагрузочного тестирования **Tsunami**.  
Диаграммы выполнены в нотации PlantUML и предназначены для использования в ВКР.

---

## Предметная область

**Tsunami** — CLI-инструмент нагрузочного тестирования HTTP-сервисов, написанный на Go.  
Инструмент позволяет:
- отправлять HTTP/gRPC-запросы с заданной скоростью (RPS) к целевому сервису;
- контролировать количество параллельных соединений и воркеров;
- собирать метрики в реальном времени (задержки, статус-коды, ошибки);
- отображать результаты в терминале или экспортировать в JSON;
- управлять тестом через REST API и веб-интерфейс с WebSocket-стримингом метрик.

## Описание диаграмм

### 1. Диаграмма вариантов использования (`use_case.puml`)

**Акторы:**
- **CLI User** — запускает `tsunami attack` из командной строки.
- **Web User** — взаимодействует через React SPA или REST API.
- **System** — таймер длительности теста и обработчик системных сигналов (SIGINT).

**Ключевые варианты использования:**
- Запуск HTTP / gRPC нагрузочного теста.
- Настройка параметров атаки (URL, rate, workers, duration, headers).
- Просмотр метрик в реальном времени (прогресс-бар / WebSocket-поток).
- Остановка теста, получение итоговых результатов, загрузка JSON-отчёта.
- Загрузка `.proto`-файла для gRPC-тестирования.

---

### 2. Диаграмма классов (`classes.puml`)

Отображает статическую структуру двух основных пакетов:

**`internal/attack`** — ядро движка нагрузки:
- `AttackConfig` — конфигурация теста.
- `GlobalMetrics` — потокобезопасный агрегатор метрик (с циклическими буферами).
- `RequestResult` — результат одного HTTP-запроса.
- `MetricsReport`, `Summary`, `LatencyPercentiles`, `ErrorBreakdown` — структуры JSON-отчёта.
- Интерфейсы `Runner` и `MetricsWriter`.

**`cmd/server`** — HTTP/WebSocket-сервер:
- `TestSession` — сессия теста со статусом и каналом остановки.
- `SessionManager` — управляет единственной активной сессией.
- `Handlers` — HTTP-обработчики REST API.
- `Hub` / `Client` — WebSocket-хаб и клиент на основе gorilla/websocket.
- DTO-типы: `StartRequest`, `MetricsPayload`, `ResultsResponse` и др.

---

### 3. Диаграмма последовательности (`sequence.puml`)

**Сценарий:** веб-пользователь запускает HTTP-тест через REST API и получает метрики через WebSocket.

Показывает:
1. Разбор и валидацию `StartRequest`.
2. Создание `TestSession` через `SessionManager`.
3. Параллельный запуск горутин: `runAttack` и `streamMetrics`.
4. Цикл сбора метрик в `GlobalMetrics` воркерами.
5. Трансляцию метрик через `Hub` каждые 50 мс.
6. Завершение теста (`Complete`) и финальный broadcast.
7. Получение итогового отчёта через `GET /api/attack/results`.

---

### 4. Диаграмма состояний (`state.puml`)

**Объект:** `TestSession`

Состояния: `Idle → Running → Completed | Stopped | Error`

Показывает:
- Создание сессии (`SessionManager.CreateSession`).
- Переход в `Running` при вызове `Start()`.
- Нормальное завершение (`Complete`) при истечении `duration`.
- Принудительную остановку (`Stop`) по сигналу пользователя или SIGINT.
- Переход в `Error` при сбое движка атаки.
- Замену старой сессии новой при следующем тесте.

---

### 5. Диаграмма деятельности (`activity.puml`)

**Субъект:** команда `tsunami attack` (CLI)

Плавательные дорожки: `CLI`, `AttackRunner`, `Worker(×N)`, `MetricsCollector`

Показывает полный алгоритм:
1. Разбор флагов cobra и валидацию входных данных.
2. Создание HTTP-клиента с пулом соединений.
3. Параллельный запуск N воркеров, диспетчера задач с rate-limiter и коллектора метрик.
4. Обработку RequestResult: обновление счётчиков, буферов задержек, кодов статусов.
5. Ожидание сигнала остановки и корректное завершение всех горутин.
6. Вывод текстового отчёта или сохранение JSON в файл.

## Как открыть диаграммы

### VS Code
1. Установить расширение **PlantUML** (`jebbs.plantuml`).
2. Установить Java и [PlantUML JAR](https://plantuml.com/download) или Graphviz.
3. Открыть любой `.puml`-файл и нажать `Alt+D` для предпросмотра.

### JetBrains IDE (IntelliJ IDEA, GoLand и др.)
1. Установить плагин **PlantUML Integration** через `Settings → Plugins`.
2. Открыть `.puml`-файл — диаграмма отобразится в боковой панели.

### Онлайн
Вставить содержимое файла на [plantuml.com/plantuml](https://www.plantuml.com/plantuml/uml/) или [kroki.io](https://kroki.io).
